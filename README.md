## 프로젝트 로직 정리

### 1. 프로젝트 개요

**AI Comment Recommender**는 크롤링된 게시글/댓글 데이터를 기반으로, 같은 게시글 안에서 상대적으로 반응이 좋았던 댓글의 패턴을 학습하고 새 게시글에 대해 안전하고 자연스러운 댓글 후보를 추천하는 FastAPI 기반 MVP 프로젝트입니다.

이 프로젝트의 목적은 단순히 자극적인 댓글을 생성하는 것이 아니라, 게시글 맥락과 기존 댓글 반응 데이터를 바탕으로 사용자가 참고할 수 있는 댓글 후보를 점수화해 추천하는 것입니다.

### 핵심 목표

- 게시글별 댓글 좋아요 수를 상대적으로 정규화
- 좋아요 반응이 좋았던 댓글의 텍스트 패턴 분석
- 댓글 후보별 예상 반응 점수 계산
- 안전 필터를 통해 비방, 혐오, 공격적 댓글 제거
- FastAPI 기반 `/score`, `/recommend` API 제공

## 2. 전체 처리 파이프라인

```text
CSV 데이터 입력
→ 데이터 전처리
→ 게시글별 좋아요 정규화
→ 댓글 유형/텍스트 피처 추출
→ 반응 예측 모델 학습
→ 안전한 댓글 후보 생성
→ 후보 댓글 안전 필터링
→ 후보별 예상 반응 점수 계산
→ 점수순 추천 결과 반환
```

### 단계별 역할

| 단계             | 역할                                                        | 선정 이유                                           |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------- |
| CSV 로딩         | 크롤링된 게시글/댓글 데이터 입력                            | MVP에서 가장 단순하고 재현 가능한 데이터 입력 방식  |
| 전처리           | 필수 컬럼 확인, 결측치 제거, 타입 변환                      | 모델 학습 전 데이터 오류를 줄이기 위함              |
| 좋아요 정규화    | 같은 게시글 안에서 댓글 반응을 상대 평가                    | 게시글 규모 차이로 인한 좋아요 수 왜곡 방지         |
| 텍스트 피처 추출 | 댓글 길이, 질문 여부, 웃음 표현, 공감/인사이트 표현 등 추출 | 댓글 반응에 영향을 줄 수 있는 구조적 특징 반영      |
| 모델 학습        | 반응이 좋았던 댓글 여부 예측                                | 새 댓글 후보의 예상 반응 점수를 계산하기 위함       |
| 후보 생성        | 안전한 템플릿 기반 댓글 후보 생성                           | 1차 MVP에서는 생성형 AI보다 통제 가능한 방식이 적합 |
| 안전 필터링      | 공격적/혐오/비방성 댓글 제거                                | 좋아요 조작·스팸·유해 댓글 생성을 방지              |
| 랭킹             | 후보별 점수를 계산하고 상위 댓글 반환                       | 사용자가 바로 참고 가능한 추천 결과 제공            |

## 4. 좋아요 정규화 로직

### 문제 정의

댓글 좋아요 수는 게시글 자체의 노출량, 인기, 댓글 수에 크게 영향을 받습니다.

예를 들어 좋아요 50개를 받은 댓글이라도, 댓글이 수천 개 달린 게시글에서는 평범한 댓글일 수 있고, 댓글이 5개뿐인 게시글에서는 매우 반응이 좋은 댓글일 수 있습니다.

따라서 절대 좋아요 수를 그대로 사용하지 않고, **같은 게시글 내부에서 상대적으로 반응이 좋았는지**를 기준으로 판단합니다.

### 적용 로직

```python
df["like_rank_pct"] = df.groupby("post_id")["like_count"].rank(pct=True)
df["label"] = (df["like_rank_pct"] >= 0.8).astype(int)
```

### 생성 컬럼

| 컬럼                    | 의미                                       |
| ----------------------- | ------------------------------------------ |
| `like_rank_pct`         | 같은 게시글 안에서 댓글 좋아요 순위 백분위 |
| `label`                 | 상위 반응 댓글 여부                        |
| `comment_count_in_post` | 해당 게시글의 댓글 수                      |
| `is_top_comment`        | 상위 댓글 여부                             |
| `is_bottom_comment`     | 하위 댓글 여부                             |

### 선정 이유

이 방식은 게시글별 노출량 차이를 보정할 수 있습니다.
프로젝트의 핵심은 “전체 댓글 중 좋아요가 많은 댓글”을 찾는 것이 아니라, **같은 맥락 안에서 상대적으로 좋은 반응을 얻은 댓글 패턴을 학습하는 것**입니다.

## 5. 댓글 텍스트 피처 추출 로직

댓글의 내용과 구조를 모델이 이해할 수 있도록 수치형 피처로 변환합니다.

### 기본 텍스트 피처

| 피처                | 설명                | 예시                                |
| ------------------- | ------------------- | ----------------------------------- |
| `comment_length`    | 댓글 글자 수        | 짧은 감탄형인지, 긴 설명형인지 판단 |
| `word_count`        | 단어 수             | 댓글의 정보량 추정                  |
| `question_count`    | 물음표 개수         | 질문형 댓글 여부 판단               |
| `exclamation_count` | 느낌표 개수         | 감정 강조 여부 판단                 |
| `laugh_count`       | `ㅋㅋ`, `ㅎㅎ` 개수 | 자연스러운 구어체/유머 표현 판단    |
| `has_question`      | 질문 포함 여부      | 댓글이 대화를 유도하는지 판단       |
| `has_laugh`         | 웃음 표현 포함 여부 | 캐주얼한 반응 여부 판단             |

### 선정 이유

좋아요를 많이 받는 댓글은 단순히 내용만 좋은 것이 아니라, 길이, 말투, 질문 여부, 공감 표현, 유머 표현 등 형식적 특징도 영향을 줍니다.

따라서 댓글을 단순 텍스트로만 보지 않고, 반응에 영향을 줄 수 있는 구조적 요소를 별도 피처로 분리했습니다.

## 6. 유형별 댓글 분류 로직

1차 MVP에서는 복잡한 딥러닝 분류 모델 대신, 키워드 기반의 가벼운 유형 분류 방식을 사용합니다.

이는 데이터가 적은 초기 단계에서 결과를 해석하기 쉽고, 추천 댓글의 안전성을 통제하기 쉽기 때문입니다.

### 댓글 유형

| 유형       | 설명            | 대표 표현                           | 역할                                        |
| ---------- | --------------- | ----------------------------------- | ------------------------------------------- |
| `empathy`  | 공감형 댓글     | 공감, 와닿, 맞아요, 진짜            | 사용자의 감정적 반응을 자연스럽게 표현      |
| `insight`  | 인사이트형 댓글 | 핵심, 결국, 중요, 관점, 설계, 정의  | 게시글에 대한 해석이나 관점을 추가          |
| `question` | 질문형 댓글     | 무엇인가요?, 어떻게?, 왜?           | 대화를 유도하고 댓글 흐름을 자연스럽게 확장 |
| `casual`   | 캐주얼형 댓글   | ㅋㅋ, ㅎㅎ, 진짜, 생각보다          | 너무 딱딱하지 않은 자연스러운 반응 제공     |
| `negative` | 부정/위험 표현  | 별로, 최악, 싫다, 꺼져, 멍청        | 점수화 또는 안전 필터링에 활용              |
| `general`  | 일반형 댓글     | 특정 유형에 강하게 속하지 않는 댓글 | 기본 후보군으로 사용                        |

## 7. 유형별 점수화 기준

### 공감형 댓글

```text
예: "이 부분은 진짜 많은 사람들이 공감할 만한 내용이네요."
```

공감형 댓글은 게시글의 감정적 맥락에 반응하는 유형입니다.
정보량이 아주 많지는 않지만, 사용자가 부담 없이 남길 수 있고 자연스러운 반응을 만들 수 있습니다.

### 인사이트형 댓글

```text
예: "결국 핵심은 기술 자체보다 그 기술을 어떻게 활용하느냐인 것 같아요."
```

인사이트형 댓글은 게시글의 내용을 한 단계 해석하거나 요약하는 유형입니다.
포트폴리오 관점에서는 가장 중요도가 높은 유형입니다. 단순 감탄보다 “왜 이 댓글이 좋은지” 설명하기 쉽고, 반응 예측 모델의 근거로도 사용하기 좋습니다.

### 질문형 댓글

```text
예: "이 내용을 실제로 적용할 때 가장 어려운 점은 무엇일까요?"
```

질문형 댓글은 작성자나 다른 사용자의 추가 반응을 유도할 수 있습니다.
다만 질문이 너무 일반적이면 반응이 낮을 수 있으므로, 게시글의 핵심 주제와 관련된 질문을 생성하는 방향이 적합합니다.

### 캐주얼형 댓글

```text
예: "이건 생각보다 현실적인 문제라 더 와닿네요 ㅋㅋ"
```

캐주얼형 댓글은 플랫폼 친화적인 말투를 반영합니다.
특히 블로그, 유튜브, 커뮤니티 댓글에서는 너무 딱딱한 문장보다 자연스러운 구어체가 반응을 얻을 가능성이 있습니다.

### 부정/위험 표현

```text
예: "별로인데요", "최악이네요"
```

부정 표현은 무조건 제거하지는 않지만, 1차 MVP에서는 안전성을 우선하기 위해 공격적이거나 비방성 표현은 필터링합니다.
프로젝트 목적이 댓글 조작이나 논쟁 유도가 아니므로, 유해하거나 자극적인 댓글은 추천 대상에서 제외합니다.

## 8. 안전 필터링 로직

### 목적

댓글 추천 시스템이 자극적이거나 공격적인 댓글을 추천하지 않도록, 후보 댓글 생성 이후 안전 필터를 적용합니다.

### 필터링 기준

| 기준             | 설명                                            |
| ---------------- | ----------------------------------------------- |
| 최소 길이 제한   | 너무 짧고 의미 없는 댓글 제거                   |
| 최대 길이 제한   | 지나치게 긴 댓글 제거                           |
| 금칙어 포함 여부 | 비방, 욕설, 혐오 표현 제거                      |
| 공격적 표현 여부 | 타인을 직접적으로 조롱하거나 모욕하는 표현 제거 |

### 예시 금칙어

```python
BLOCKED_KEYWORDS = [
    "죽어",
    "꺼져",
    "멍청",
    "병신",
    "혐오",
    "최악",
]
```

### 선정 이유

이 프로젝트는 좋아요를 많이 받기 위한 자극적 댓글 생성기가 아니라, **안전하고 맥락에 맞는 댓글 추천 도우미**를 목표로 합니다.

따라서 점수가 높게 예측될 수 있는 표현이라도, 유해하거나 공격적인 표현은 추천 결과에서 제외합니다.

## 9. 반응 예측 모델 로직

### 목적

댓글 후보가 주어졌을 때, 해당 댓글이 좋은 반응을 얻을 가능성을 예측합니다.

### 입력값

모델은 댓글 텍스트에서 추출한 피처를 입력으로 사용합니다.

```text
comment_length
word_count
question_count
exclamation_count
laugh_count
has_question
has_laugh
empathy_score
insight_score
negative_score
```

### 출력값

```text
댓글이 좋은 반응을 얻을 가능성 점수
```

API에서는 이 점수를 0~100 사이의 값으로 변환해 반환합니다.

```json
{
  "comment": "결국 문제를 정의하는 능력이 중요해질 것 같아요.",
  "score": 79.0
}
```

### 모델 선정 이유

1차 MVP에서는 복잡한 딥러닝 모델보다 `scikit-learn` 기반의 가벼운 분류 모델을 사용합니다.

선정 이유는 다음과 같습니다.

- 데이터가 적은 초기 단계에서 빠르게 학습 가능
- 피처 기반 예측 구조를 설명하기 쉬움
- 모델 결과를 디버깅하기 쉬움
- FastAPI 서비스에 가볍게 연결 가능
- 추후 임베딩 피처나 더 큰 데이터셋으로 확장 가능

## 10. 댓글 후보 생성 로직

1차 MVP에서는 LLM을 바로 붙이지 않고, 템플릿 기반 후보 생성을 사용합니다.

### 선정 이유

초기 단계에서 LLM을 바로 사용하면 다음 문제가 생길 수 있습니다.

- 생성 결과 통제가 어려움
- 안전성 검증이 복잡함
- 프로젝트의 핵심인 “반응 예측 로직”보다 생성 품질에 집중이 분산됨
- API 키, 비용, 외부 의존성이 생김

따라서 1차 MVP에서는 안전한 후보 댓글을 먼저 생성하고, 모델이 이를 점수화하는 구조로 구현합니다.

### 후보 생성 예시

```python
[
    {
        "type": "insight",
        "comment": "결국 핵심은 기술 자체보다 그 기술을 어떻게 활용하느냐인 것 같아요."
    },
    {
        "type": "casual",
        "comment": "이건 생각보다 현실적인 문제라 더 와닿네요 ㅋㅋ"
    },
    {
        "type": "empathy",
        "comment": "이 부분은 진짜 많은 사람들이 공감할 만한 내용이네요."
    }
]
```

## 11. 추천 랭킹 로직

댓글 후보가 생성되면 다음 순서로 최종 추천 결과를 만듭니다.

```text
1. 게시글 입력
2. 댓글 후보 생성
3. 안전 필터 적용
4. 각 댓글 후보의 피처 추출
5. 반응 예측 모델로 점수 계산
6. 점수 높은 순으로 정렬
7. top_k개 댓글 반환
```

### 반환 예시

```json
{
  "post_text": "AI 시대에 개발자는 어떻게 살아남아야 할까?",
  "recommendations": [
    {
      "rank": 1,
      "type": "insight",
      "comment": "결국 핵심은 기술 자체보다 그 기술을 어떻게 활용하느냐인 것 같아요.",
      "predicted_score": 79.0
    },
    {
      "rank": 2,
      "type": "casual",
      "comment": "이건 생각보다 현실적인 문제라 더 와닿네요 ㅋㅋ",
      "predicted_score": 68.0
    }
  ]
}
```

### 선정 이유

단순히 댓글을 하나 생성하는 방식보다, 여러 후보를 만들고 점수화해 정렬하는 방식이 더 안정적입니다.

이 구조는 추천 시스템의 기본 흐름과 유사하며, 포트폴리오에서도 다음 역량을 설명하기 좋습니다.

- 데이터 전처리
- 피처 엔지니어링
- 반응 예측 모델링
- 후보 생성
- 안전 필터링
- API 서빙

## 12. FastAPI API 구조

### `GET /health`

서버 상태 확인용 API입니다.

```json
{
  "status": "ok"
}
```

### `POST /score`

사용자가 직접 댓글 후보를 입력하면, 각 댓글의 예상 반응 점수를 계산합니다.

#### 요청 예시

```json
{
  "post_text": "AI 시대에 개발자는 어떻게 살아남아야 할까?",
  "comments": [
    "결국 문제를 정의하는 능력이 중요해질 것 같아요.",
    "좋은 글 감사합니다.",
    "이건 생각보다 현실적인 문제라 더 와닿네요 ㅋㅋ"
  ]
}
```

#### 역할

- 사용자가 직접 작성한 댓글 후보 평가
- 댓글 후보 간 상대 점수 비교
- 모델 점수화 기능 검증

---

### `POST /recommend`

게시글 본문만 입력하면, 시스템이 안전한 댓글 후보를 생성하고 점수순으로 추천합니다.

#### 요청 예시

```json
{
  "post_text": "AI 시대에 개발자는 어떻게 살아남아야 할까?",
  "top_k": 5
}
```

#### 역할

- 게시글 기반 댓글 후보 추천
- 후보 생성 → 안전 필터 → 점수화 → 랭킹 전체 흐름 검증
- 1차 MVP의 핵심 API

## 13. 현재 MVP 범위

현재 1차 MVP는 다음 범위까지 구현하는 것을 목표로 합니다.

```text
[완료] CSV 기반 데이터 입력
[완료] 댓글 데이터 전처리
[완료] 게시글별 좋아요 정규화
[완료] 텍스트 피처 추출
[완료] 반응 예측 모델 학습 및 저장
[완료] 댓글 후보 점수화
[완료] 안전 필터링
[완료] 추천 랭킹
[완료] FastAPI Swagger 문서 확인
```

현재 버전은 기능 흐름 검증을 위한 MVP이므로, 모델 성능 자체보다는 **전체 추천 파이프라인이 끝까지 동작하는 것**에 초점을 둡니다.

---

## 14. 현재 한계

### 1. 데이터 수 부족

현재 샘플 데이터는 모델 성능을 평가하기에 부족합니다.
따라서 Accuracy, F1 Score 등의 수치는 실제 성능 지표로 해석하지 않고, 파이프라인 동작 확인용으로만 사용합니다.

### 2. 키워드 기반 유형 분류

현재 댓글 유형 분류는 키워드 기반입니다.
이 방식은 빠르고 해석하기 쉽지만, 문맥을 깊게 이해하지는 못합니다.

예를 들어 `문제`라는 단어는 비판 표현일 수도 있지만, `문제 정의`처럼 긍정적인 인사이트 표현일 수도 있습니다.

### 3. 템플릿 기반 후보 생성

1차 MVP에서는 안전성과 구현 속도를 위해 템플릿 기반 후보 생성을 사용합니다.
따라서 게시글마다 완전히 맞춤화된 댓글을 생성하는 데는 한계가 있습니다.

### 4. 임베딩 기반 맥락 유사도 보완 필요

프로젝트 구조상 `sentence-transformers`를 활용한 게시글-댓글 의미 유사도 분석으로 확장할 수 있습니다.
추후에는 `post_comment_similarity` 피처를 추가해 게시글 본문과 댓글 후보가 얼마나 의미적으로 잘 맞는지 반영할 예정입니다.

## 15. 개선 방향

### 1. 데이터셋 확장

최소 목표:

```text
게시글 20개 이상
게시글당 댓글 5개 이상
총 댓글 100~200개 이상
```

추천 목표:

```text
게시글 50개 이상
댓글 500개 이상
```

데이터가 늘어나면 게시글별 좋아요 정규화와 모델 평가가 더 의미 있어집니다.

### 2. 임베딩 피처 추가

`sentence-transformers`를 사용해 게시글 본문과 댓글의 의미 유사도를 계산합니다.

```text
post_embedding
comment_embedding
post_comment_similarity
```

이를 통해 단순히 길이와 키워드가 좋은 댓글이 아니라, 게시글 맥락에 맞는 댓글을 더 잘 추천할 수 있습니다.

### 3. 모델 개선

현재는 기본적인 scikit-learn 기반 모델을 사용합니다.
추후에는 다음 모델과 비교할 수 있습니다.

```text
LogisticRegression
RandomForestClassifier
GradientBoostingClassifier
XGBoost
LightGBM
```

비교 기준:

```text
Accuracy
Precision
Recall
F1 Score
ROC-AUC
게시글 단위 Group Split 성능
```

### 4. 유형 분류 고도화

키워드 기반 분류를 다음 방식으로 개선할 수 있습니다.

```text
Sentence-BERT 임베딩 기반 클러스터링
댓글 유형 분류 모델 학습
LLM 기반 댓글 의도 분류
BERTopic 기반 댓글 군집화
```

### 5. 안전 필터 고도화

현재는 금칙어 기반 필터링을 사용합니다.
추후에는 다음 방식으로 개선할 수 있습니다.

```text
욕설/혐오 표현 분류 모델
스팸성 댓글 탐지
정치/성별/외모 공격 탐지
허위정보 단정 표현 탐지
```

## 16. 프로젝트 핵심 차별점

이 프로젝트는 단순한 댓글 생성기가 아닙니다.

```text
단순 생성형 댓글 AI
→ 댓글을 그럴듯하게 생성하는 데 집중

AI Comment Recommender
→ 기존 댓글 반응 데이터를 분석하고,
   게시글 맥락에 맞는 안전한 댓글 후보를 점수화해 추천
```

핵심 차별점은 다음과 같습니다.

- 좋아요 수를 절대값이 아니라 게시글 내부 상대값으로 정규화
- 댓글 유형과 구조적 피처를 분리해 분석
- 안전 필터를 통해 자극적 댓글 추천 방지
- 후보 댓글을 생성한 뒤 모델 기반으로 랭킹
- FastAPI 기반으로 실제 서비스 형태의 API 제공
